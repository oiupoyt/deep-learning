# Doublecheck spec

## Goal
Ship "deep-learning", a native DeepSeek Harness plugin porting LearnHarness's learning loop (measure, plan, teach, practice), persistent knowledge graph, background roles, and editable prompts - installed in the live web profile, deterministic tests green, and verified end to end by the user with models they pick.

## Scope
In scope: a single plugin package "deep-learning" in projects/deep-learning (new repo, dual-pushed) - plugin server code (tools, prompt composition, phase machine, question pending/grading, background role loops: researcher/demo/visual/pdf, extractor→auditor→merger pipeline, wake delivery), pure core modules (contracts, question-core, plan-tree parser, phases, graph merger/simplification/derivation, coverage, clusters, layout), plain-file stores under $DSH_HOME/deep-learning/ (chats metadata, graph ledgers, prompts overrides, settings), client bundle (Learning main panel with graph canvas + chain table + notes import + new teach/practice drafts, toolview cards for quiz/probe/explain/problem/conclude/plan_init/artifacts, composer-dock question companion, plan panel, settings section "Deep Learning"), skills/deep-learning read-only field guide, deterministic tests incl. golden fixtures, README/NOTICE. Out of scope: DSH core changes, DSH's own UI pages, provider/key management (harness), Electron concerns.

## Acceptance criteria
1) Plugin installs cleanly via link into ~/.dsh/profiles/web (package.json dep + bundles list) and the web profile boots with it. 2) `npm run typecheck`, `npm run build`, `npm test` all pass in the plugin repo; tests are deterministic (no network, no LLM). 3) A full teaching session runs end to end in the GUI: measure (probe tool questions with thinking+confidence), plan (plan_init mermaid tree, live plan panel), teach (predict/check cycle with reveal law, repairs), using the user-picked session model. 4) A practice session poses problems via the problem tool, accepts thinking submissions, concludes with verdict + reveal. 5) The graph persists across sessions and server restarts (ledgers under $DSH_HOME/deep-learning/graph/); extraction runs after turns; home Learning panel renders canvas + chains; notes import works. 6) Prompts are visible and editable (segment files + overrides honored at composition). 7) Roles never hardcode models: conversation = session picker, background roles = settings pins. 8) Golden fixtures pin real on-disk formats. 9) User performs the final manual E2E checklist and confirms. 10) README covers install, usage, and role->settings mapping; NOTICE attributes amosblomqvist/learnharness; AGPL-3.0 kept.

## Failure modes
1) Model call fails mid-question: question tool call stays visible; harness synthesizes interrupted result on crash-resume; model re-poses (accepted delta vs LH free mid-question resume). 2) Background role model not configured/pin invalid: the role refuses honestly with a clear message; conversation continues; settings page surfaces the missing pin. 3) Extraction failure: checkpoints nothing (LH law); uncovered messages re-run on next trigger; per-chunk isolation keeps sibling merges. 4) Corrupt/dangling ledger lines: strict shape guards drop invalid lines, never guess; deleting a proposition cascades to referencing chains. 5) Plugin disabled or crashed: DSH must keep booting (plugin failure must not take down the profile); its slots/rows disappear cleanly. 6) Missing services (browser, speech, web-search): features degrade honestly (buttons hidden, tools report unavailable) - never fake results. 7) Race on question answers: pending-answer keyed by tool call id; double answers rejected; aborts resolve with an interrupted verdict. 8) Wrong question authoring (ungradeable correctAnswer, bad nodeId): error result back to the model, retried in-turn (ported Gate-3).

## Priorities
Correctness of the learning loop and graph integrity first (merger determinism, question grading, phase machine) - these are the product. Behavior parity over convenience: when porting is ambiguous, match LearnHarness as-built and flag, never silently redesign. KAT Square Minimalist theme + antislop filter for all UI. Deterministic tests before shipping; golden fixtures updated in the same commit as any on-disk format change. Performance of the canvas/layout only needs real-data scale (thousands of nodes), not synthetic stress. Fine to ship v0.1 without: cluster hull polish, mermaid ad-hoc diagrams beyond plan_init, per-node confidence analytics.

## Non-goals
1) Porting LearnHarness's own provider list, key storage, OAuth bridges, Electron shell, or auto-updater (harness owns these). 2) Hardcoding any model id anywhere. 3) Copy-pasting or importing LearnHarness's React components - layout/interaction design is matched, code reimplemented. 4) Resurrecting the dead problem-set pipeline (partitioner/generator/grader, /practice pages) - as-built practice sessions only. 5) Deepgram dictation (DSH speech-to-text replaces it; if the STT service is absent, dictation hides - no keys of our own). 6) LH appearance/font settings (harness theme owns them). 7) No new global keyboard-map changes beyond the plugin's own surfaces. 8) No changes to DSH core packages. 9) English-only v0.1 UI.
